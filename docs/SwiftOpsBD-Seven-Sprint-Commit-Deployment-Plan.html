Commit procedure for every sprint

# 1. Stage only the listed files for one commit
git add <exact paths>

# 2. Review; press q to exit the diff viewer
git diff --cached --stat
git diff --cached

# 3. Commit only if staged content matches the message
git commit -m "<message from the sprint table>"

# 4. Confirm what remains
git status --short

Push strategy

Recommended: create all Abdul baseline commits locally through Sprints 2–7, run the complete tests/build, then push each repository once. This avoids repeatedly deploying partially integrated production code while preserving every logical commit in Git history.

Final backend push

cd /d/SoftwareProject/swyftopsbd-api
npm run lint
npm test
git diff --check
git status --short
git log --oneline --decorate -40
git push origin main

Final frontend push

cd /d/SoftwareProject/swyftopsbd
npm run lint
npm run build
git diff --check
git status --short
git log --oneline --decorate -40
git push origin develop

If Vercel production watches main, merge develop into main using a reviewed pull request.

Yusuf timing

  1. Abdul pushes the complete backend baseline.
  2. Yusuf clones SwyftOpsBD-API from GitHub.
  3. Yusuf creates one branch per assigned Jira QA task.
  4. Yusuf creates new tests/evidence and fixes only reproduced defects.
  5. Yusuf opens pull requests; Abdul reviews and merges them.
  6. Render redeploys after each accepted backend pull request.

Files never committed

  • .env, .env.local and Firebase service-account JSON
  • Stripe, Supabase or Barikoi secret values
  • node_modules/, dist/, uploads/
  • Real NIDs, licenses, medical documents or user uploads

Stop condition

If lint, tests, build, secret review or staged-diff review fails, do not push. Correct the current sprint while its changes are still isolated.
